①黑客松是什么：限时把痛点变成能演示的作品

先花 60 秒对齐这个词——它和你印象中的"程序员通宵比赛"已经不是一回事了。

黑客松（Hackathon）就是限时做出一个能现场演示的解决方案的比赛。它不考理论、不评文档，核心动作只有三个：选一个真问题 → 做出最小可演示版 → 讲给评审听。

老印象

  • 程序员的通宵编程马拉松
  • 比谁的技术难、代码多
  • 不会写代码就只能旁观
  • 没做完上台很丢人

2026 年的现实

  • Anthropic 官方赛 13,000 人报名，五个获奖者里只有一位是软件工程师 官方公布
  • 冠军是加州律师（建筑许可审批工具），季军是心脏科医生（患者陪伴工具）
  • Claude Code 创始人的评语："领域知识胜过编程语法"
  • 比的是选题、取舍和表达——恰好都是业务同事的主场
💡 所以"不需要懂代码"不是主办方的客气话，是这两年全球黑客松的真实走向：做出来已经很便宜了，知道该做什么才值钱。最了解业务痛点的人——也就是你——本来就站在起跑线前面。

②我们这场和一般黑客松，差在哪四件事？

我 7 月底做过一轮调研（精读了 60 篇参赛复盘和各大赛事的官方规则），结论是：外面的经验不能直接搬，这场有自己的规则。

差在哪一般黑客松我们这场
时间24–48 小时现场冲刺拉几个月：征集 → 辅导 → 半决赛 → 决赛，已经落地在用的项目也欢迎参赛
比什么常常比技术含量官方明说"不是程序员比赛、不需要懂代码""不是比谁工程量大"——比的是真实业务问题 + 实际改善
评审工程师、技术专家业务条线专家、院区/集团领导、飞书专家——听业务故事的人
门槛现场从零开始写官方问答原文："只要你的作品使用了飞书和 AI 能力"，DIG 和飞书专家还全程陪跑
💡 一句话总结：这场比赛离"创业路演"近，离"编程马拉松"远。要准备的不是技术答辩，是一个让评审记得住的业务故事，外加一个当场跑得通的演示。

③考点：评审到底看什么？

官方材料里关于"怎么评"的每一句话我都抠出来了。核心标准只有一句，值得背下来。

官方核心标准原文："是否来源于真实业务问题，并能体现 AI 对效率、质量、服务或管理的实际改善。"决赛评审明列三个维度：创新性、业务价值、可推广性。拆开是四个考点：

考点 1真实业务问题 ⭐
官方材料里出现频率最高的要求——"来自业务现场的小痛点"被反复强调。
自查：开场能不能具体到"哪个岗位的谁、每月哪件事被烦到"？说不出具体的人，就还不够真实。
考点 2业务价值，用数字讲 ⭐
评分语言写的是"实际改善"——定性的"大幅提升"几乎不计分，前后对比的数字才算数。
自查：有没有一句"原来 X → 现在 Y"？没有的话，这周最要紧的作业就是它。
考点 3可推广性（这场特有）
"跨院区、跨 BU 复制推广的可能"是决赛明列维度——外面的比赛没有这条，最容易被忽视。
自查：别的部门拿走你的作品，要改什么、要什么权限、谁来维护？答得出三步，这个维度就稳了。
考点 4创新性
在内部赛里，创新性不等于技术新，而是切入角度新：别人还在想的题你已经做完、别人做登记表你做决策工具。
自查：你的作品和"在 Excel 上再加一列"有什么本质区别？讲得出来就是创新。
⚠️ 一个隐性考点：报名表本身就是评分表的镜像——"当前进展"和"预期或已产生价值"是独立字段，意味着已落地 > 试点中 > 还是想法。我们四个项目全部已落地或上线，这是我们整体的先天优势，讲的时候别浪费。
三件还没公布的事（我去大赛群里问，结果同步给大家）
  • 三个维度有没有评分权重、各占多少
  • 每队展示几分钟、能不能放 slides
  • 8/15 BU 初审的具体形式（交材料？现场讲？）

⑤外面赛场验证过、这场仍然管用的六条打法

来自评审自述和获奖者复盘（出处见文末附录），全部翻译成这场比赛的用法。

  1. 第一句先把东西说清，再带一个数字。"这是一个让〔谁〕的〔哪件事〕从〔X〕变成〔Y〕的工具。"评审连着看很多项目，记不住铺垫，只记得住这样一句话。
  2. 先讲问题，让评审跟你一起烦。评审里有院区领导和业务负责人，"排班排到晚上九点""Excel 台账对不上"这类场景他们有切身体感——时间分配参考：问题占三成，方案占七成。
  3. 90 秒内让人看到东西在跑，而且只走一条流程。调研里评审的原话："一个强项目配一个让人困惑的演示，会输给一个评审能听懂的简单项目。"想展示的第二条流程？删掉。
  4. 先写演示脚本，再打磨功能。五个要素：一句话问题（绑定到一个具体的人）→ 现在这个人怎么绕、代价多少 → 演示从哪个动作开始 → 唯一要评审记住的瞬间 → 收尾接到推广上。写不出脚本，说明还没想清楚要给评审看什么。
  5. 录一段 60–90 秒的完整备份录屏。这是全部调研里共识度最高的一条，评审、获奖者、翻车者的说法完全一致：现场网络和投屏一定会出状况，没有录屏等于没有后手。本地存一份、云端存一份。
  6. 提前背四个必答题——评审问的问题其实高度固定，见下表。
评审大概率会问会掉分的答案会加分的答案
"具体是谁在用？""我们部门"点名到岗位："医疗服务部的排班员，每月底排下月班的那位"
"省了多少时间？""大幅提升了效率"一个前后对比数字，外加这个数字怎么算的
"别的院区能直接用吗？""应该可以"复制三步：改什么配置、要什么权限、谁来维护
"AI 和飞书具体用在哪一步？""整体都用了 AI"指到具体功能："简历 OCR 这一步是飞书智能体做的"
⚠️ 这里我先认领一个反面教材：7 月中帮排班工具写报名简介时，"手工排一次班要多久"这个数字我没拿到，简介里只能写"最大限度降低排班工作量"——这种定性说法在评审那里几乎不计分。各队现在补数字完全来得及，而且多半只需要问当事人一句话。

⑥我们四个项目，各自怎么切题才有胜算

以下亮点全部来自各队的实际产物（代码、截图、上线系统）——都是评审追问时你能当场打开给他看的东西。每队最后的三条升级动作，就是本周作业。

🗓️ 排班工具（医疗服务部）—— 切"效率 + 管理改善"

亮点在哪能看到用在哪
自动排班结果和排班员手工排的真实 7 月班表完全一致，含请假绕排、顶班医疗服务部专版 + 当月真实班表逐格对照演示的高潮：现场加一条请假 → 一键重排 → 结果和人工一致
通用版 + 医疗专版两个版本，复制这条路已经走通过一次同目录两个独立文件"可推广性"必答题的答案主体
规则在页面上点选，排班员自己维护；单文件、数据不出本机设置面板 + 白盒说明切"不用懂代码"的比赛基调；数据安全追问的答案

本周升级动作：① 问排班员拿数字——手工排一次班多久、现在多久（一句话的事）；② 讲清接飞书的下一步——排班结果已能导出 CSV，接飞书多维表格做全院区看板是现成路径 规划；③ 集团医院板块的培育池里有一个"儿科排班"还在想法阶段——同一个痛点在两个 BU 独立冒头，恰好说明这是集团级的真问题，而我们这版已经落地验证，可以直接给儿科用。这段话提前准备好。

🧑‍💼 人才库（HR 团队）—— 切"效率 + 服务"，全场飞书含量最高

亮点在哪能看到用在哪
8 个 AI 能力真实接在招聘流程里：简历图片 OCR、简历结构化、自动打标、岗位匹配分析、匹配打分、人才库 AI 问答、人才摘要系统后台的能力配置，逐个可指认"AI 用在哪一步"必答题——四个项目里 AI 证据最扎实的，也是飞书专家最想听的部分
建在飞书上、已经上线，与多维表格双向同步飞书工作台可直接打开最有机会成为飞书对外讲的标杆案例——可以主动讲给飞书专家听
库里已有 1,603 名候选人（硕士 376、博士 10），双库 + AI 筛选 + 九宫格盘点系统数据概览页开场那句话里的数字；"当前进展"的硬数据

本周升级动作：① 拿一次真实急招举例——从"业务提需求"到"给出候选人名单"，原来多久、现在多久；② 演示就现场跑一次真实筛选（AI 筛选 → 匹配打分 → 九宫格），把"快"演出来而不是说出来；③ 简历是敏感个人信息，提前准备好数据权限的回答（谁能看、有没有脱敏）——领导评审可能比技术评审更在意这个。

📊 理赔数据可视化分析工具（核保团队）—— 业务价值离钱最近

亮点在哪能看到用在哪
从 v3.0 到 v3.7 的迭代记录全写在工具里，每一版都有"为什么改"——"真实在用"最过硬的证据形态工具的版本日志"当前进展"字段；证明这不是为参赛赶出来的东西
一条流水线打通：理赔报表 Excel 丢进去 → 自动分析 → 出 12 个页签的可视化报告（总赔款、案均、高额重疾、管控建议……）→ 可导 PPT工具 + 生成的报告文件对照演示主线，只演这一条："上传 → 出报告"
28 个分析维度，对应渠道客户真的会问的问题分析报告目录讲"业务复杂度"用——一句带过，别展开

本周升级动作：① 拿一份真实渠道报告举例——原来出一份要几天、现在几分钟；② 把 28 个维度压成 3 个渠道故事（"渠道问为什么赔付涨了 / 哪些医院贵 / 明年怎么管控——以前答一个要拉几天数据，现在打开就有"），半决赛对条线专家可以展开细节，决赛对领导只讲这三个故事；③ 报告的分发可以走飞书（群 / 云文档），这半句就把飞书元素接上了。

💳 实体会员卡管理平台（运营团队）—— "当前进展"全场最实

亮点在哪能看到用在哪
已部署上线、14 个活跃用户，操作日志里是不同同事的真实核销、盘点记录系统仪表盘 + 最近操作记录（带真名和时间戳）演示时直接翻日志给评审看——"自己人真在用"最能打动院区领导
18 种卡样、6,041 张库存、7 种低库存自动预警，横跨十余家合作方仪表盘统计卡 + 卡样清单讲痛点的真实性：这么多合作方的卡混在 Excel 台账里，错一张要人工翻半天
入库 → 盘点 → 流水 → 核销 → 导出全流程线上化，含权限管理系统功能树对比句："以前是一张 Excel 轮流填，现在是一套有流水、有权限、有预警的系统"

本周升级动作：① 补数字——月底对一次账原来几小时、现在几分钟；② "与核心保单数据暂时隔离"这一点，建议讲成主动的稳健选择："上线初期先在物料库存这个低风险域跑稳，再谈接核心系统"——提前把这段话想好，别现场组织语言；③ AI 的角色如实讲在开发侧：运营团队两个人用 Claude Code 把系统做了出来——这本身就是"效率先锋"主题最直接的例证，不需要硬造产品内的 AI 功能。

💡 如果有机会把四个作品放在一起讲：它们正好覆盖"效率先锋"的四种形态——排班（管理）、招聘（服务）、理赔分析（业务价值）、物料库存（流程），而且全部出自业务团队自己之手。这就是我们的集体故事：AI 不是 IT 部门的项目，是每个部门手里的工具。

⑦从今天到 8/15：每队的作业清单

BU 初审前 10 天，真正不能省的就这六件事，每队加起来不超过 4 小时。

  1. 本周内拿到你的"原来 X → 现在 Y"。四个队缺的数字惊人一致，而且都只需要问当事人一句话。这是优先级最高的作业。
  2. 写演示脚本（五要素），定下"一句希望评审转述的话"。演示围着这句话做，装不进这句话的功能不演。
  3. 把讲稿里每句话对到能当场打开的东西。对不上的删掉——半决赛评审是懂行的业务条线专家，经不起虚的。
  4. 录 60–90 秒备份录屏，本地 + 云端各存一份。
  5. 8/11–8/13 模拟答辩。我来组织：用 Claude 分别扮演业务条线专家和飞书专家，对每队跑一轮追问，四个必答题过关为止。
  6. 三件没公布的事我去群里问（初审形式 / 展示时长 / 评分权重），结果同步到群里。
⚠️ 别等半决赛通知才动手——8/15 的 BU 初审就要按 20% 筛人，材料现在就要按"能打"的标准准备。
