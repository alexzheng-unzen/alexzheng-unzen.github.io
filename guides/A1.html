Claude Code 入门指南

从「用不起来」到「真的好用」，关键就在第一周。 新人 90% 的挫败感不来自工具，而来自前期没建立好 context—— 而早期 context 怎么来？靠 Prompt。这份指南，只讲一件事：早期怎么把 Prompt 写到位。

阅读约 8 分钟 面向：新接触 Claude Code 的同事 v1.0

为什么你会觉得 CC「不好用」？

和身边同事聊下来，新人的挫败感几乎都能归到三个根本原因。 这三件事不解决，再聪明的模型用着也会让人崩溃。

❶ 「它好像没听懂我在说什么」

真相：CC 不知道你能接收什么格式的回复。 你想要表格？bullet？直接改文件？还是 PPT 大纲？ 不说，它就用默认猜——而默认猜往往不对。

❷ 「它做出来的东西不是我要的」

真相：你的「交代」在它眼里不够清晰。 CC 像一个聪明、但完全不了解你业务的实习生。 你必须告诉它三件事：① 目标是什么 ② "完成"长什么样 ③ 不要做什么。

❸ 「昨天明明做对了，今天怎么又错了？」

真相：它没有跨对话的长期记忆。 每开一个新对话，它就是「失忆」状态。 除非你把规则写进 CLAUDE.md 或 /memory， 否则昨天的指导，今天还要重来一遍。

三个痛点，三个解法

下面每个解法都配上命令演示，跟着敲一遍就会。

SOLUTION 01

用 Plan Mode 强制对齐方案

解决 痛点 ❶ + ❷：听不懂 / 做错了

在 Claude Code 终端里，按 Shift + Tab 切到 Plan Mode（你会看到底部状态栏变色），然后再提你的需求。

claude-code
⏸ plan mode on (shift+tab 切换模式) › 帮我做一个理赔数据清洗工具： 输入是 CSV，输出 Excel， 要能给非技术同事用 ─ Plan ────────────────────────────── 1. 读取 CSV，识别编码（GBK/UTF-8） 2. 按字段清洗：去空、合并重复行 3. 输出 .xlsx + 自带使用说明 4. 打包成 .exe，双击可跑 › _ ← 你看完方案再决定要不要让它跑
为什么有效：在 Plan 阶段改方向只要 30 秒， 写完代码再改要 30 分钟。先让它说，再让它做。
SOLUTION 02

用 CLAUDE.md 给它建一份「员工手册」

解决 痛点 ❸：昨天交代过的事情今天又错

在你的项目根目录运行 /init，CC 会生成一个 CLAUDE.md。这个文件会在每次新对话开始时被自动读取。

claude-code
› /init ✓ Created CLAUDE.md ✓ This file is loaded into every conversation

然后把「每次都要解释一遍的事」写进去：

CLAUDE.md
# 关于我 - 角色：运营 / 设计 / 营销（按你的实际写） - 系统：Windows 11 + PowerShell + 中文用户名 # 文件存放规则 - C 盘永不落地 - D 盘：代码和半成品 - E 盘：给同事的最终交付物（zip / PDF / exe） # 输出偏好 - 中文回复 - 给非技术同事的工具必须"白盒化" - 改完代码必须实跑一次再交付，不能只静态 review
为什么有效：写一次永久生效。从此 CC 不会再把文件丢到 C 盘， 也不会忘记你是 Windows 用户。这是最高 ROI 的一次性投入。
SOLUTION 03

用 /memory 让它记住业务事实

解决 痛点 ❸「失忆」的跨项目版本

CLAUDE.md 是项目级规则（只在这个项目生效）， /memory 是账号级长期记忆（所有对话都能调用）。

claude-code
› /memory 📝 Edit your long-term memory (Claude will recall this across all conversations)

适合写进去的

  • ✅ 公司全称、业务一句话介绍、品牌色（如「主色 #2D5F8D」）
  • ✅ 你的英文名拼写、常用同事名字、部门缩写
  • ✅ 你的输出偏好（例：PPT 默认 16:9、文档默认中文）

不要写进去的

  • ❌ 一次性任务、临时调试细节
  • ❌ 涉密信息（客户名单、内部财务数据）
小心机：把「你公司是干嘛的」写进去， CC 给的建议会立刻变专业——它知道你不是泛泛做事，而是在某个具体行业里做事。

写 Prompt 的三段式模板

第一周还没建立好 CLAUDE.md 的时候，每次提需求按这个结构走。 这是新人最该背下来的一个模板。

prompt-template
› 【目标】 我要做什么 例：把这个 CSV 转成飞书能导入的 Excel 【上下文】 环境 / 限制 / 参考 例：Windows 11，文件在 E:\xxx\， 参考我之前给的模板（已附在对话里） 【验收标准】 "完成"长什么样 例：双击 .exe 就能跑，非技术同事也能用， 遇到错误要弹中文提示

对比一下效果差异：

业余 Prompt专业 Prompt
「帮我做个工具处理这个表格」 上面那个三段式
CC 写一个能跑、但你用不上的脚本 CC 写一个你同事第一次见就会用的 .exe
你来回修 5 轮还不对 一次到位，剩下时间能干别的

实战中磨出来的小习惯

下面 6 条是真实工作中磨出来的。每条都会讲清楚：什么意思 · 为什么这样做 · 具体怎么操作。

📎 HABIT 01

参考材料优先：能给图就别打字

一句话讲清楚：CC 看图比读字快。一张截图能省你 500 字的描述。

为什么这样做："现代风格""高级感"这种词每个人理解都不一样，CC 也不例外。但你扔一张图过去，它能直接读出来配色、布局、字体感觉。

怎么操作：

  • 直接把图片拖进对话框就行
  • PDF、Word、Excel 也都能拖
  • 截屏后 Ctrl+V 也能粘贴
claude-code
› [拖入 reference.png] 做一个像这样风格的着陆页， 配色换成 #2D5F8D ✓ 已识别 1 张参考图 → 提取到：极简排版、大间距、深色 CTA → 准备按此风格生成，配色已替换
真正的窍门：与其打"做一个现代风格的页面"， 不如截一张你看上眼的网站丢给它，说"做一个像这样的，配色换成 #2D5F8D"。
🌍 HABIT 02

让 CC 注意「环境差异」——你不用自己懂环境

一句话讲清楚：你电脑能跑的东西，发给同事可能就打不开。让 CC 自己注意这个问题，比你自己学环境知识简单 100 倍。

为什么这样做：

  • 你装了 Node.js、Python，同事电脑里没有
  • 你用 Mac，同事用 Windows
  • 你用 Office，同事用 WPS
  • 不说，CC 默认按"开发者环境"写——普通同事打不开很正常

怎么操作：你不用自己知道环境细节，把下面这句话扔给 CC 就行：

prompt 模板
› 我做的东西最后要发给同事，他们用 Windows + WPS， 没装任何开发环境。请确保我做出来的东西 能让他们双击打开就用，避免任何只在我电脑能跑的写法。 ───────────────────────────────────── ✓ 已记录约束： · 优先生成 .exe / .html（自带依赖） · 避免需要装 Node / Python 才能跑的方案 · 文件路径不用中文，避免乱码
真正的窍门：把"环境约束"当成 prompt 的固定开头。 CC 会自动选兼容性最好的方案——比如打包成 .exe 而不是 .py 脚本、 生成单文件 HTML 而不是要装 Node 的应用。
✅ HABIT 03

验收看真东西，别只信「完成 ✅」

一句话讲清楚：CC 经常"自我感觉良好"——它说完成了，但实际可能跑不起来。

常见翻车现场：

  • 文件夹里有 .exe，但双击没反应
  • HTML 打开是空白页
  • "成功生成 Excel"——打开是乱码

怎么操作：每次让它做完事，加一句话强制验收：

prompt 模板
› 做完之后帮我自己跑一下，截一张图给我看是不是正常的。 如果跑不起来你自己改，不要让我手动 debug。
真正的窍门：CC 能自己跑程序、自己截图、自己 debug。 它不主动做，只是因为你没要求。要求一下，验收质量立刻上一个档次。
📦 HABIT 04

白盒化：给同事的工具要「透明」

专业名词翻译：
· 黑盒＝你只看到结果，中间发生什么是「黑」的，看不见
· 白盒＝每一步都告诉你做了什么，结果可以自己验证对错

同一个任务，两种交付效果对比：

❌ 黑盒（不推荐）
› 处理这 100 条理赔单 ✓ 完成 [文件已生成] 同事打开发现少了几条， 不知道是被过滤了， 还是工具坏了—— 只能跑来找你。
✅ 白盒（推荐）
› 处理这 100 条理赔单 📥 输入：100 行 CSV 📋 规则：去重 → 合并金额 → 标记异常 ⚙️ 过程： · 跳过 3 行重复 · 标记 5 行金额异常 📊 结果：92 条有效 + report.txt ⚠️ 异常：第 27 行金额为 0 ✅ 自检：金额加总 = 输入总和 📌 边界：未处理超长字符串

给同事做工具时，明确要求 CC 实现"白盒化七项"：

  1. 输入：处理了什么数据
  2. 规则：按什么规则处理
  3. 过程：每一步做了什么
  4. 结果：输出在哪、有多少
  5. 异常：哪些数据没处理 / 报错
  6. 自检：结果对不对（比如总数是否守恒）
  7. 边界：什么情况不处理（说清楚比假装能处理强）
真正的窍门：把这 7 项写进 CLAUDE.md， 所有项目自动遵循。同事用了出问题，他自己就能看出是哪一步—— 不会再跑来问你。
🤝 HABIT 05

多 Agent 协作：选对工具 + 省钱思路

一句话讲清楚：不要把所有任务压在一个 AI 上。每个 AI 擅长的事不一样，搭配着用更香。

目前手上常用工具的强项：

工具强在哪适合干
Claude Code 综合实力强、对话理解好、代码质量高 新项目首选、复杂逻辑、写代码、做工具
Codex (GPT-5/4) 第二意见、深度 debug、有时 review 很猛 Claude 卡住了让 Codex 看、交叉验证
Kimi 长文本、中文搜索、读 PDF 强 调研、读长文档、找资料
OpenClaw 飞书集成、轻量自动化 群机器人、跟同事的接口

💰 外面听回来的省钱思路

workflow
阶段 1：调试 → 用 Claude Code 或 Codex 把"做什么、怎么做"跑通， 调出一个能用的 prompt + 流程 + 模板 阶段 2：执行 → 换便宜模型批量跑 比如 Haiku、GPT-4o-mini 同样的 prompt，token 单价低 10-100 倍 ✓ 结果：质量没掉太多，成本砍掉一个数量级
真正的窍门：把 Claude Code 当你的"研发"， 便宜模型当你的"流水线工人"。 研发算账要算质量，流水线算账要算成本。
什么时候要用这招：要处理的数据特别多、单次任务要跑几百上千次、 token 不够用的时候——这是个救命思路。
🧹 HABIT 06

一对话一任务：上下文越干净越准

一句话讲清楚：一个对话只解决一件事，别在一个窗口里东聊西聊。

为什么这样做：

  • CC 会"记住"同一对话里前面聊过的所有内容
  • 上下文越乱，它越容易把不相关的事串在一起
  • 你做完任务 A 跳到任务 B，CC 可能用 A 的思路解 B（错得很隐蔽）

怎么操作：

claude-code
# 做完一件事，清空对话 › /clear ✓ Conversation cleared. CLAUDE.md + /memory 保留。 # 或者直接开新窗口（推荐）
真正的窍门：把一个对话当一次"会议"—— 议程清晰、结束就散。不要开一个对话当"全天客服"。
放心：CLAUDE.md 和 /memory 不会被清，长期规则永远在。

早期 context 不够时，Prompt 就是 context。

把「目标 + 上下文 + 验收标准」说清楚，
把「规则」写进 CLAUDE.md， 把「事实」写进 /memory。
做到这三件事，你已经用得比 80% 的人都顺了。
