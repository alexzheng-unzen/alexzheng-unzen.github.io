先记住一件事：AI 很健忘

它没有记忆。你和它说的每句话、发给它的每个文件，都记在一个「工作本子」里。你每发一条消息，它都要把整个本子从头读一遍，才知道该干嘛——读的每一页都要花钱。所以本子越厚、越乱，每句话就越贵，它还越容易看花眼。今天的所有技巧，说白了就是：把对的活交给对的工具，再让本子保持薄而干净。

AI 是来干活的，放心用。这一课教你用得又快又省。

按任务查：点标签看细节

写周报、改稿、总结长文、整理会议纪要——这类日常文字活，占大家用量的大头。

用什么：网页版就够（claude.ai / 豆包 / Kimi）。要动本地文件（一堆 Word 批量改）才开 Claude Code。
哪档模型：主力档 Sonnet 或 DeepSeek，够快够好；简单的活便宜档就行。
  • 一次把要求说全：改哪里、改成什么样、口吻保持不变。
  • 让它参考现成的好稿子，别让它凭空自由发挥。
  • 换一个新任务，就开一个新对话（别在一个窗口里从周一聊到周五）。

翻文献、翻涉外文书、整批文件翻译——翻译是最典型的"量大、单件简单"的活。

哪档模型：直接上便宜档（DeepSeek、通义千问 turbo）。翻译这种活，最贵的模型和便宜的差别很小，价钱却能差几十倍。
关键：中文内容优先用国产模型——又便宜，中文还算得省。
  • 先拿 1 个文件试翻，看质量满不满意、大概花多少钱，再决定要不要整批放量。
  • 一个文件一个对话，别把几十个文件堆进同一个窗口（否则每翻一个，前面所有文件都被重读一遍，钱就这么烧的）。
  • 术语表 / 要求放在开头固定不动，能省钱。

做 PPT、一页纸、海报、营销物料——需要出"好看的东西"的活。

用什么：首选 Claude Design（网页里对话就能生成设计稿，可以导出成 PPT / PDF）。
别这么干：把 PPT 丢进写代码的工具，让最贵的模型反复"美化"——又贵又不对路（第④节细讲）。
  • 专门做设计的产品，比让通用模型硬凑排版，效果好得多。
  • 复杂视觉可以先让它出几版草稿，你挑一版再细调。
  • 公司有品牌规范和插画包，做对外物料先套用，风格才统一。

汇总表格、清洗数据、对账、生成报表——运营和财务的高频活。

用什么：要处理本地 Excel / 一堆文件，用 Claude Code（能直接读写你电脑里的文件）。一次性的小表格，网页版发上去也行。
哪档模型：主力档起步；每周都要跑的固定活，让它帮你做成一个小工具，之后一键复用。
  • 把文件的完整路径直接给它，别让它自己满电脑找。
  • 说清楚要什么结果（汇总哪一列、按什么分组），别只说"帮我处理一下"。
  • 重复三次以上的活，就值得固定成工具——做一次，以后近乎免费。

把一堆资料变成"能问答的知识库"——比如保险条款库、产品手册问答。

用什么：两个零件配合——Embedding 模型负责"找得准"（把资料变成能被检索的形式，超便宜），主力档模型负责"答得好"。
最关键的一步：资料先清洗干净再入库。答得准不准，八成定在这一步。
  • 图片版 PDF、格式乱的文件，先转成干净文本再入库。
  • Embedding 是"检索零件"，不是用来聊天的——别搞混。
  • 这类项目建议找懂的同事一起起步，公司已经有跑通的例子。

③花多少钱，心里有个数

不用记价格表，记住两件事就够：模型分档，越难的活才用越贵的档。

先建立一个体感

AI 按"字数"收费（术语叫 token，1 个汉字约合 1 个 token 上下）。一个直观的参照：让旗舰模型读完约 700 页 A4 文档，大概 ¥30。单看不贵——真正烧钱的是两件事：让最贵的模型干便宜活，和让它把没用的内容反复重读。

模型就三档，按活的难度选

便宜档 · 跑量

DeepSeek · 通义千问 turbo · Haiku · 豆包 mini

翻译、格式转换、批量摘要、打标。量大、单件简单的活全用它，比旗舰便宜几十倍。

主力档 · 日常

Sonnet · DeepSeek 旗舰 · 文心 · 豆包

写文书、整理报表、改稿、邮件。日常绝大多数活的主力，够快够好。

旗舰档 · 硬活

Opus · GPT 旗舰 · 通义千问 max

复杂方案、深度分析、重要对外文稿。一天也就几件，好钢用在刀刃上。

④两个最常见的误区

都是刚上手时容易踩的坑，换个开法就能省一大截。

一句话看懂

钱，基本都烧在这两件事上

✗ 让最贵的模型干便宜活

翻译、美化这类活，便宜档就干得很好；用旗舰档，价钱翻几十倍，效果差不多。

✗ 让它把没用的内容反复重读

几十个文件挤在一个对话里，每问一次，全部内容都被从头读一遍——本子越厚，每句话越贵。

同样的翻译量：换对模型 + 分开处理，从几百块 → 一块多。

误区一 · 把 PPT 丢进写代码的工具，让最贵的模型反复"美化"

❌ 容易踩的开法✅ 正确的开法
用最贵的旗舰模型，对着整份 PPT 反复"再美化一下"，每改一次全文重写一遍——一个下午几百块。用 Claude Design：对话式改设计、直接导出 PPT，含在订阅里。真要改代码，也让它只改样式、别重写全文，用主力档就够。

误区二 · 一大堆文件一次丢进去，用最贵的模型逐个翻

❌ 容易踩的开法✅ 正确的开法
几十个文件塞进同一个对话，用旗舰档一个个翻——每翻一个，前面所有文件都被重读一遍，钱成倍烧。先拿 1 个文件用便宜档试翻、看质量；满意后一个文件一个对话，或让 Claude Code 写个脚本自动挨个跑。
先想在哪干、用哪档，再拿一个小样试跑——三步走完再放量。

⑤让花销看得见

看得见，才管得住。按你用的工具，把"计价器"打开就行。

用网页版（claude.ai / 豆包 / Kimi）

订阅制，不按次收费，随便用，不用盯着花销——这是最省心的起点。想知道额度用了多少，看账号页的用量条即可。

用 VS Code 插件挂 API（Cline / Roo Code）

这类工具按量付费，界面顶部会实时显示每次请求花了多少钱。习惯就一个：每提交一轮，抬头扫一眼那个金额。前面两个误区，只要当时看了这个数，第三轮就会停下来。

用 Claude Code

三条命令帮你看清账：

/context 看本子里都装了什么、还剩多少 /usage 看这次花了多少、额度还剩多少 /statusline 配一次，让花销常驻显示在底部，不用反复敲

界面上的金额是估算，用来建立体感；真实账单以各平台后台（Anthropic / OpenAI / 火山 / DeepSeek 的用量页）为准。

If any of these is you, this lesson is for you. The company wants everyone to use AI freely and often. AI is here to do the work for us. What you actually need to learn is not how to use less, it is how to give the right job to the right tool.

First, one thing to remember: AI forgets

It keeps no memory of past chats, and it only works with what is in the current chat and the files you attach. Picture that as one "notebook." Every message and file you add goes into the notebook, and each time you send something the model works through the notebook again to answer, so every page in it adds to the cost. The thicker and messier the notebook, the more each message costs, and the easier it is for the model to lose track. Every technique today comes down to this: give the right job to the right tool, and keep the notebook thin and clean.

AI is here to do the work. Use it freely. This lesson shows you how to do it fast and cheap.

Weekly reports, edits, long summaries, meeting notes. This everyday text work is the bulk of what people use AI for.

What to use: the web app is enough (claude.ai / Doubao / Kimi). Open Claude Code only when you need to touch local files, such as editing a batch of Word docs.
Which tier: the workhorse tier, Sonnet or DeepSeek, is fast and good; simple jobs run fine on the low-cost tier.
  • Say the whole request at once: what to change, how, and keep the tone the same.
  • Give it a good draft to follow. Don't let it invent freely.
  • New task, new chat. Don't run one window from Monday to Friday.

Papers, foreign-language documents, whole batches of files. Translation is the classic high-volume, low-difficulty job.

Which tier: go straight to the low-cost tier (DeepSeek, Qwen Turbo). For translation the priciest model and the low-cost one differ little in quality, but the price differs by tens of times.
Note: for Chinese text the Chinese models are both cheaper and count Chinese more efficiently.
  • Test-translate one file first. Check the quality and the rough cost before you run the whole batch.
  • One file, one chat. Don't pile dozens of files into a single window, or every earlier file gets reread each time you translate the next one. That is how the money burns.
  • Keep the glossary and instructions at the top, unchanged. That saves money.

Slides, one-pagers, posters, marketing material. Work where the output has to look good.

What to use: start with Claude Design, Claude's tool for turning a chat into design drafts (then export to slides or PDF), included in the subscription.
Don't do this: drop a slide deck into a coding tool and have the priciest model "polish" it again and again. It costs a lot and it is wrong for the job (section ④ has the detail).
  • A product built for design beats forcing a general model to lay out a page.
  • For complex visuals, have it draft a few versions, pick one, then refine.
  • The company has brand guidelines and an illustration pack. Use them for outward-facing material so the style stays consistent.

Summarizing tables, cleaning data, reconciling accounts, building reports. High-frequency work for operations and finance.

What to use: for local Excel or a batch of files, use Claude Code (it reads and writes files on your computer directly). For a one-off small table, the web app is fine.
Which tier: start with the workhorse tier; for a fixed job you run every week, have it build you a small tool, then reuse it in one click.
  • Give it the full file path directly. Don't make it hunt around your computer.
  • Say what result you want (which column to sum, how to group). Don't just say "help me sort this out."
  • Any job you repeat more than three times is worth turning into a tool. Build it once, then it is nearly free.

Turning a pile of documents into a knowledge base you can ask questions of, such as a policy-terms library or a product-manual Q&A.

What to use: two parts work together. An embedding model handles "find the right passage" (it turns documents into a searchable form, very cheap); a workhorse model handles "answer well."
The step that matters most: clean the documents before you load them. Roughly eight in ten of your answer quality is decided here.
  • Scanned PDFs and messy files: convert them to clean text before loading.
  • Embedding is the retrieval part, not a chat model. Don't mix the two up.
  • Start this kind of project with a colleague who knows it. The company already has working examples.

③Know roughly what it costs

You don't need to memorize a price list. Two things are enough: models come in tiers, and only harder work needs a pricier tier.

Build a feel for it first

AI charges by text volume (the term is token: one English word is about 1.3 tokens, one Chinese character about 0.6 to 2 depending on the model). A simple reference: having a flagship model read about 700 pages of A4 costs roughly US$4.4 (about ¥30). On its own that is not much. The real money goes to two things: making the priciest model do cheap work, and making it reread useless content over and over.

Just three tiers, chosen by difficulty

Low-cost · volume

DeepSeek · Qwen Turbo · Haiku · Doubao mini

Translation, format conversion, batch summaries, tagging. Use it for anything high-volume and simple. Tens of times cheaper than a flagship.

Workhorse · daily

Sonnet · DeepSeek flagship · Ernie · Doubao

Writing documents, tidying reports, editing, email. The workhorse for most daily work. Fast and good.

Flagship · hard jobs

Opus · GPT flagship · Qwen Max

Complex plans, deep analysis, important outward-facing writing. A few a day at most. Use it only when the job genuinely needs it.

📌 One line to remember: for Chinese-language work, use the Chinese models. Their list price is lower and they count Chinese more efficiently. Two savings at once.

④The two most common mistakes

Both are easy traps when you start. A different approach saves a big chunk.

In one line

This is where the money goes

✗ Making the priciest model do cheap work

Translation and polishing run fine on the low-cost tier. On a flagship the price multiplies by tens of times for about the same result.

✗ Making it reread useless content over and over

Dozens of files crammed into one chat. Every question rereads all of it. The thicker the notebook, the more each message costs.

Same translation volume, right model and separate chats: from a few hundred RMB down to about ¥1. That is roughly 64 times cheaper.

Mistake 1 · Dropping slides into a coding tool and having the priciest model "polish" over and over

❌ The easy wrong way✅ The right way
Use the priciest flagship, tell it to "polish this some more" across a whole deck, and rewrite the full text each pass. A few hundred RMB in one afternoon.Use Claude Design: edit the design by chat, export straight to slides, included in the subscription. If you really must edit code, have it change only the styling, not rewrite the text, and the workhorse tier is enough.

Mistake 2 · Dumping a pile of files in at once and translating them one by one on the priciest model

❌ The easy wrong way✅ The right way
Dozens of files in one chat, translated one at a time on a flagship. Each translation rereads every earlier file, so the cost compounds.Test one file on the low-cost tier first and check the quality. Once happy, one file per chat, or have Claude Code write a script to run through them automatically.
Decide where to run it and which tier, test a small sample, then scale. Three steps, in that order.

⑤Make spending visible

You can only control what you can see. Turn on the meter for whatever tool you use.

Web app (claude.ai / Doubao / Kimi)

Subscription, not pay-per-use, so use it freely without watching the cost. This is the easiest place to start. To see how much of your quota is left, check the usage bar on your account page.

VS Code extensions on an API key (Cline / Roo Code)

These tools are pay-per-use, and the top of the interface shows in real time what each request cost. One habit: after every round you submit, glance at that number. For the two mistakes above, seeing that number at the time would have made you stop by the third round.

Claude Code

Three commands help you read the bill:

/context: see what is in the notebook and how much room is left /usage: see the estimated cost and remaining quota /statusline: keep the cost visible at the bottom (set once)

The number on screen is an estimate, for building a feel. The real bill is in each platform's dashboard (the usage pages for Anthropic / OpenAI / Volcano Engine / DeepSeek).
