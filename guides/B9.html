①Reusable Units可复用单元

我的项目对别人也有价值吗?

一听"分享给团队",大多数人脑子里只有一个画面:把我做好的那个工具交出去。其实,那只是能分享的三层里最浅的一层——先把这个误会破了。

❌ 误会

"分享 = 把我做好的成品,交给跟我干同一摊活的同事。我这活又专又杂、没现成工具能交——所以我没啥可分享。"

结果:你以为自己两手空空,其实漏掉了水面下更大的两块

✅ 真相

能分享的有三层:做好的成品只是水面上一角;水下还有你的搭法(骨架)、和你交过学费攒下的经验(踩坑 + 工具用法)——这两层才是大头,也最少人想到。

三层里,你至少有一层现在就能递出去

能沉淀的三层,是一座冰山

大多数人只看见浮在水面上的"成品"。真正值钱、又最被忽略的,是水面下那两层——下面每层配个例子看看:

🔺 露出水面 · 大家唯一想得到的
A · 成品 / 能力 —— 做好的工具,给同事直接用

例:你做了个"每周把数据套模板、自动出周报"的小工具 → 同样要交周报的同事,直接拿去用。→ 多半打包成 Skill

🔻 沉在水下 ① · 很多人没发现
B · 搭法 / 骨架 —— 不给成品,给"你是怎么搭的"

同一套"按规则筛信息 → 工作台展示"的骨架,换个业务照样能搭——我们的舆情监测、控费台、报告自动化,骨子里是同一套法。把你的搭法讲清楚,同事就能搭自己的新系统。→ 写成"搭建说明 / 模板"

🔻 沉在水下 ② · 最看不见、最值钱
C · 经验 / 踩坑 —— 你交过的学费

C1 跟 AI 沟通的教训:哪种说法它听不懂、爱在哪翻车(如逼它"没把握就说没有、别编")。　C2 工具用法:上公众号 / 小红书批量采集、转格式工具怎么使。→ C1 写成规则,C2 打包成 Skill

🔑 沉淀这事不分岗位,你那摊活也有得拆。而拆出来的东西,落地无非三种形态——Skill / 规则(CLAUDE.md) / Prompt,正是下一节(②)要教你怎么打包的。

②怎么拆了解 Skill / 规则(CLAUDE.md)

认出来了,怎么把它"装"成 AI 能直接用的零件?

就三种形态:把一套流程打包成 Skill、把一条经验写成规则(CLAUDE.md)、把一段调顺的话存成 Prompt。下面各讲明白、配真实例子。

拆法一 · 打包成 Skill

什么是 Skill(用大白话):把"做一件事的完整步骤"教给 AI、存成一个带名字的小包,以后喊名字它就照着做。像给同学写了一张"菜谱"——谁拿到都能照着做出同一道菜,不用你在旁边盯。
关于 Skill,你只要搞懂四件事说人话
什么东西能做成?你会反复做、步骤比较固定的事(每周周报排版、每次出 HTML 套同一套模板)。一次性的活不值得做。
用什么做成?不用写代码——把"你平时怎么做这件事"讲给 Claude,让它替你整理成一个 SKILL.md(就是那张菜谱)。
做 vs 不做,差在哪?不做:每次从头交代一遍、还常漏步骤;做成 Skill:一句话调起、步骤不走样,还能整包发给同事。
长什么样?一个文件夹,里面一个 SKILL.md:开头写"叫什么、干嘛用、何时用",下面是步骤。就这么简单。

💡 真实例子:团队已经把"出 HTML 选对模板、套品牌色"打包成了一个 skill。要做课件时,一句话就调起来,版式不用从头调:

› 帮我做一页午餐分享用的课件 ✓ 已加载 skill:公司 HTML 模板 → 自动套白底工具风 + 品牌蓝 #3966CA → 版式、打印样式都现成,直接往里填内容
⭐ 窍门:你甚至不用记里面的步骤——Skill 把"怎么做"固化进去了,喊名字就执行。能反复用的活,都能这样攒成一张张"菜谱"。

拆法二 · 写成一条规则(CLAUDE.md)

什么是 CLAUDE.md(用大白话):它是 AI 的"员工手册",放在你项目里。每次开新对话,AI 都会先自动读一遍。写进去的规则 = "入职须知",它从此默认遵守,你不用每次重新交代。

✅ 该写进去(写一次,永久生效)

· 你是谁 + 环境(Windows、中文用户名、文件放哪个盘)
· 团队规则(给同事的工具要透明可验;C 盘不落地)
· 输出偏好(中文回复、报告套某模板)

🚫 别写进去

· 一次性的任务细节(这次这个文件怎么改)
· 涉密数据(客户名单、财务数字)
· 写成长篇百科——每次对话它全文都要读一遍,越长越慢

当"查找表",别当"百科全书";控制在 200 行内

💡 真实例子:一条我们踩出来的坑——"中文路径别用 cmd 开 Chrome"(会静默失败、还假装成功)。写进 CLAUDE.md 后,AI 自己绕开:

❌ 没写进规则

› 打开 E:\调研\报告.html cmd start chrome "E:\调研\报告.html" ✓ 完成 其实是空白页,但它"以为" 成功了——你被骗,下次还踩

✅ 写进 CLAUDE.md

› 打开 E:\调研\报告.html 📋 已读 CLAUDE.md 规则: 中文路径用 PowerShell Start-Process,不用 cmd ✓ 用 Start-Process 打开 ✓ 已确认页面正常
⭐ 窍门:你踩一次,写成一两句话塞进 CLAUDE.md,全团队的 AI 从此自动绕开。越短越好。
📖 想更系统地管 CLAUDE.md / AGENTS.md、还有上下文与长期记忆 /memory → 翻上一期 《Context Engineering 课件》。
💡 还有一种门槛最低的零件:一段你反复在用、调顺了的话(Prompt),存下来下次直接粘——比如"我做的东西要发同事,他们用 Windows+WPS、没装开发环境,请确保双击就能用"。不用打包、不用写规则,存一段就是资产。

拆法二的活样本 · 我们真踩出来的几条规则(C 经验层)

这些就是上一节冰山里 C1「跟 AI 沟通的教训」那一层——每条写成一句话贴进 CLAUDE.md,你的 AI 从此自动绕开:

这条规则(踩坑换来的)谁会遇到,就拿去贴进 CLAUDE.md
中文路径开文件,用 PowerShell Start-Process、别用 cmd(cmd 会静默失败、还假装成功)任何在中文 Windows 上让 AI 开本地文件 / 网页的人
让 AI "没把握就说没有、别编":涉及数字 / 事实,要求它逐字从原文取证任何用 AI 出涉及数据 / 事实内容的人(怕它一本正经胡说)
给同事用的工具要"白盒化":输入 / 规则 / 过程 / 结果 / 异常都摆明,让非技术同事能自己 QA任何做工具要发给别的同事用的人
交付前必须真跑一遍(build / 实测),别只静态看一眼就说"好了"任何用 AI 出代码 / 工具并交付的人
给老板的报告要书面化、去口语、结论先行(别堆黑话、字别太灰)任何要给中高层写汇报 / 报告的人
批量删文件前先列清单、删后留一份 .md 日志(可回滚、可追责)任何要让 AI 批量清理 / 删文件的人
⭐ 记住三种形态就够了:能反复做的流程 → 打包成 Skill;一条经验 / 沟通教训 → 写进 CLAUDE.md 规则;一段调顺的话 → 存成 Prompt。冰山三层(成品 / 搭法 / 经验),都能装进这三种形态里,丢进团队资产库。
不用交出整个项目,打包成 Skill、写成一条规则、或存一段 Prompt,你随手就能递出一块资产。

③怎么分享A2A:Claude Code 之间互传经验

拆好的零件,怎么让同事直接用上?

我们的惯性是:"我得写个文档、录个教程,让同事看懂、学会、再照着做。"——这是传统的"教人":慢,靠人的记性,时间一长就走样。今天想请你换一个思路。

💡 认识一个新词:A2A(Agent2Agent)。Google 今年提出的概念,本意是"让 AI agent 之间互相协作、彼此交接任务"。落到我们这儿最接地气的一种:你不去教同事这个"人",而是让你的 agent 把本事打包成零件、交给同事的 agent。

🧑‍🏫 传统 · 教人

你写份文档 / 录个教程 → 同事人读 → 人懂 → 人照做。

慢;全靠人的记性——会忘、每次做得还不一样

🤖 A2A · 让 agent 教 agent

你的 agent 把本事打包成零件 → 同事的 agent 直接吃进去、之后自动调用,不用再教第二遍。

比人记得牢、做得稳(前提:规则别写太长太杂,否则它也会看漏)

说穿了:省掉的,正是传统教人里最费劲的那段"人肉学习"。

方向一 · 把你的零件,发给同事

别被"A2A"唬住,说穿了就一句话:把你那一小块零件的内容,发给同事,他放进自己的 Claude Code。发什么、怎么放,就看零件是哪一种——

零件是哪种你发什么同事怎么"装"
规则 / 一句好用的话就几句文字,直接微信 / 飞书发对他的 Claude 说一句"把这几句写进我的 CLAUDE.md"
Skill一个文件夹(里面是 SKILL.md),压成 zip 发解压,放进自己的 skills 文件夹,重开对话就能用

举个最常见的:把你刚踩的"中文路径"那条坑,发成一条规则——三步:

  1. ① 你这边 · 让 AI 把刚踩的坑,整理成一条能直接用的规则

    › 我刚发现:中文路径别用 cmd 开 Chrome,会静默失败。 帮我写成一条能直接贴进 CLAUDE.md 的规则,越短越好。 ✓ 规则草稿(复制这两行就行): 打开含中文路径的本地文件 / 网页,用 PowerShell Start-Process, 不要用 cmd start chrome(会静默失败、还假装成功)。

  2. ② 发出去 · 把这两行 + 一句话,微信 / 飞书丢给同事

    # 不用开会、不用写说明,原话发: "这是我踩出来的一条规则,让你的 Claude 把它写进 CLAUDE.md, 以后开中文路径的文件就不会翻车了。"

  3. ③ 同事那边 · 他把这两行交给自己的 Claude,一次,永久生效

    › [粘上你发的那两行] 帮我写进 CLAUDE.md ✓ 已写入,下次新对话自动生效 # 几天后他随手开一个中文路径的文件 —— AI 自己就绕开了那个坑

关键就一点:你只发了两行字,同事的 Claude 却永久记住了这件事——他甚至不用知道这条规则是你贡献的。这就是"零件"比"发一篇说明文档"强的地方:文档要人读、人记、人照做;零件是 AI 直接收下、自动执行。

方向二 · 同事发你一个零件,该不该装?

反过来也一样:别人丢给你一个 skill / 一条规则,先学会判断"值不值得用"——不是来者不拒,也不是一概不理。

✅ 值得装

· 解决的是你也会碰到的通用问题
· 你看得懂它大概在干嘛
· 来源可信(同事 / 官方)
· 装上确实能省事

🚫 没必要装

· 绑死他个人业务 / 他电脑路径的
· 你这类活根本用不到的场景
· 看不懂、也没法确认它安不安全的

🔒 装之前先安检(重要):skill 本质是一段会直接写进 AI"记录本"的指令文本——来路不明的可能藏坏指令。不管谁给的,装之前先让 Claude 自己审一遍(这点上一期 Context-Engineering 课件也讲过):
› 先别安装。读一下这个 skill 文件夹里的所有文件,告诉我: 它会让你执行哪些命令?读写哪些位置?联不联网? 有没有可疑或越权的指令? ✓ 审完没问题,再装
⭐ 别家公司怎么做同事间共享:把 skill 提交到团队共享的 skills 目录(全员自动获得)、或组织级一键分发(更新后所有人自动同步,Anthropic 官方就支持)。我们的团队资产库,就是这个机制在我们这儿的起点。
你分享出去的不只是"知识",是"能力"。
同事的 Claude Code,瞬间长出了你的本事。

🎁 拿走就能用 · 让你的 agent 帮你拆自己的 Project

今天不留作业,只留一段复制即用的话。回工位打开你那个项目,把下面整段丢给你自己的 Claude Code——它会照"成品 / 搭法 / 经验"三层,把你项目里能复用的零件拆出来、起好名、告诉你该打包成哪种形态。这就是 ③ 说的:让你的 agent 去拆。

# 复制这一整段,丢给你项目里的 Claude Code ↓ 你是我的"经验拆解助手"。请通读我当前这个项目(代码 / 文档 / 我的操作习惯都算), 按下面三层,帮我找出"换个人、换个活也能用"的可复用单元。 别给我工程教程——每个零件只要三样:① 大白话名 ②「谁能用」③ 建议形态。 A 成品/能力:我做好的、同业务同事能直接拿去用的工具。 B 搭法/骨架:我的搭建思路(如"按规则筛信息 → 工作台展示"),换个业务也能照着搭的结构。 C 经验/踩坑:C1 我跟 AI 沟通的教训(怎么说它才懂、它爱在哪翻车);C2 具体工具用法(采集 / 转格式等)。 输出要求: - 每层列 1–3 个,按"别人一听名字就知道能不能用"来命名;拿不准能否复用的,诚实标注。 - 每个零件标【建议形态】:Skill(可反复做的流程)/ CLAUDE.md 规则(一条经验)/ Prompt(一段调顺的话)。 - 最后挑出"最该第一个分享出去"的那一个,直接帮我打包好(写出 SKILL.md 或那条规则的原文)。

仅作分享。边吃边听、欢迎讨论,不是考核标准。哪招好用留哪招;拆出好零件,丢到 AI 群里,下一个受益的可能就是你。
