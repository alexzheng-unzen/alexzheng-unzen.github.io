Social Listening System
社媒舆情监测系统

竞品官网、微信公众号、小红书、监管及官方网站等

①Background & Pain Point：人工收集信息，费时费力还容易漏

我们的业务涉及理赔、控费、医疗网络、产品支持等多个方向——外部环境一变，成本和服务承诺立刻受影响。所以竞品动态、监管政策、客户吐槽都是业务的直接输入。但过去，这些信息得靠每个部门自己去检索。

Before · 人找信息

  • 每个部门各自主动检索，人工收集费时费力，还容易错漏
  • 剩下的靠人脉打听、靠平台算法推送——问到什么、刷到什么算什么
  • 竞品动作、政策变化、客户投诉：被动从外界听到时，往往已经太迟
  • 各自收藏、散落群聊，无法沉淀复用，人一走就带走了

Now · 信息找人

  • 多路信源定向、大量采集：竞品官网 / 微信公众号 / 小红书 / 监管及官方网站（海外社媒亦可接入）
  • 靠 Prompt 设计快速筛选、打上标签并分级，与我们无关的直接过滤
  • 分析总结后直送各部门看板，高危舆情置顶预警
  • 全部入库、条条可回溯原文，判定标准越校越准

②How It Works：定向采集 → Prompt 筛选打标 → 送达看板

三步流水线，采集到送达全链自动衔接，人只看结果。采集端由 Exa / Tavily 搜索接口与自建浏览器运行时 agent-browser-runtime 驱动。

1Collect · 定向采集

竞品官网、微信公众号、小红书三路定期自动运行，监管及官方网站按需批量采集——按 117 个监控词定向、大量抓取。

监控词按四个维度选定：品牌与竞品舆情 37 / 产品与服务动态 27 / 政策与行业趋势 38 / 用户怨言与争议 15。小红书另设「品牌哨兵」：提到我们品牌的帖子单独盯防，每轮必查。

2Tag & Tier · Prompt 筛选打标

判定标准写进 Prompt，大模型逐条阅读、打标签、分级：Tier 1 高价值必读 / Tier 2 部门参考 / Tier 3 行业背景，与我们无关的直接过滤。

同时判断这条该送给哪个部门——系统的判断力，全在这套 Prompt 的设计里。

3Deliver · 送达部门看板

分析总结后进看板：首页滚动条播最新信号，各部门看板各看各的，高危舆情置顶预警。

每条信息可点赞 / 点踩，同事的反馈直接用于校正大模型下一轮的筛选与判级。

💡 Prompt 判定标准的演化路径：最初是我和大模型脑暴出的部门假设——猜每个部门关心什么；现在用部门问卷逐份校正，换成同事亲口说的业务口径（见 ④）。

BUser Research · 新品调研（产品团队）

目标客群与需求洞察直接取自系统采集的社媒一手数据，不再从零搜集。

少儿高端医疗险调研：用户笔记与评论中「拒赔 / 理赔难」是最高频痛点，为产品主打「理赔确定性」提供了一手依据。

Evidence · 一手数据与关键发现
  • 数据底盘：自抓 45 篇笔记正文 + 720 条真实评论 + 22 个关键词信息流；调研全程引用约 805 篇笔记 / 2.5 万条评论
  • 发现一：720 条评论中「问医生 / 在线问诊 / 家庭医生」类词 0 条——「有人告诉我没大碍」是未被言说的潜在需求
  • 发现二：话题被「比价 / 避坑 / 配置」内容压倒性占据（最高赞 8,879「新生儿保险水太深」）——获客要靠内容种草而非关键词竞价
  • 产出：目标客群画像 + 高频痛点与需求清单（JTBD）+ 竞品空白点，直接进产品调研包
CPolicy Tracking · 政策信息采集（运营部门）

政府公开信息批量采集、整理打包直接交付，不再靠人手动翻网站。

为运营同事采集国家医保局「全国医疗服务项目编码」全量数据；监管机构官方公众号列为最高优先级信源。

Evidence · 交付物与校验
  • 交付《全国医疗服务项目编码_全量.xlsx》：7,881 条项目 × 8 列字段（2026-06-17 抓取自国家医保局公开库）
  • 与官网计数接口返回值 7,881 完全一致，抽样逐字段核对吻合，无遗漏
  • 公开接口批量抓取、脚本可复现，随包附操作手册，运营同事可自行更新

  • 情报分级分布：Tier 1 高价值 464 / Tier 2 部门参考 532 / Tier 3 行业背景 181

④Calibration：Prompt 判定标准，从「我猜的」到「同事亲口说的」

系统好不好用，取决于判定标准准不准。第一版标准是我和大模型脑暴出的工程假设；部门需求问卷上线后，正逐份校正成各部门自己的业务口径。

1初始 · 和大模型脑暴假设

我和大模型一起脑暴：猜每个部门关心什么——从预授权、理赔到 HR，逐个部门列出该盯的信息，先写进分流器 Prompt 让系统跑起来。

这一版判定标准是工程假设，还没经过业务确认。

2过程 · 问卷调研真实需求

给各部门发需求问卷，让同事亲口说「什么算重要、什么不要」——答卷逐份回收、逐份固化成判定标准。

问卷按真实部门设计，同事一眼认出自己的版块。

3结果 · 校准分流器 Prompt

把同事的原话落回 Prompt：该收的补上、不该收的剔除，判定标准从「我猜的」换成各部门自己的业务口径。

问卷还推翻了我的一个原始假设——实证见下框。

Evidence · 答卷直接改写了分流器 Prompt（原 → 现）

原 Prompt：用工、社保、员工福利政策类内容 → 判给 HR（我猜的）

现 Prompt：只收具体到同业公司的人事信号（裁员 / 搬迁 / 组织调整 = 定向挖人才的时机），宏观政策类直接过滤——HR 同事的原话。

原 Prompt：预授权相关信息 → 一律判给医疗网络（我猜的）

现 Prompt：审核 / 时效 / 管控口径 → 医疗网络；被卡 / 结算卡壳（执行侧）→ 理赔运营——预授权与运营两份答卷交叉印证出的拆分规则。

其余答卷同样换回了可落地的判定信息：预授权同事把「预授权时效 / 审核时效」列进最高权重监控；保险研发同事确认创新药、医保新政对商保的影响、海外健康科技模式都要收，推荐的两个行业公众号已定向接入；运营同事给出行动触发器「竞品上了新东西，有人问我们跟不跟」，并确认「只是知道一下」也算有效——相关性闸门因此不收得过紧。

⑤For Other BUs：集团其他 BU 拿去能做什么

这套三段式架构本身不绑行业：定向采集 → Prompt 筛选打标 → 送达部门看板。已落地用户投诉预警、新品调研、政策信息采集等场景，市场、BD、战略、产品等职能都能直接套用。要换的只有三样——信源清单、监控词表、Prompt 里的判定标准。换完，它就是你们自己的情报系统。

对应已落地场景 A（危机舆情发现）：换一份品牌词表就能跑。

Product · 产品与研发

对应已落地场景 B（新品调研）：监控词表换成你们的品类即可。

Strategy & BD · 战略与商务

同业动态、监管政策、行业信号汇进一个看板定期送达，决策与谈判前情报先到位。

对应已落地场景 C（政策信息采集）：信源清单换成你们盯的机构。
