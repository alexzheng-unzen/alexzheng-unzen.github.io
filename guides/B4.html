让它一次出对：三个指令习惯

习惯差的问法对的问法
一次说全"帮我优化一下"→改完不满意→"再改改""改哪里、改成什么样、哪些保持不变"，一条说完。模糊指令的返工轮数，就是你多付的钱和时间
给参照让它凭空发挥，再来回纠偏丢一份你认可的旧稿："按这份的结构和口吻写。"有参照，一版命中率翻倍
定角色和读者直接要产出"你是保险行业的运营主管，写给分支机构负责人看"——同样的内容，措辞档次立刻不同

查资料的正确姿势

开联网搜索（对话框地球图标）之后，还有两条纪律：①要来源——"每个结论后面附来源链接"，没有来源的数字一律当它编的；②关键数字交叉核对——它给的市场规模、法规条款、竞品价格，点进原文看一眼再引用。AI 检索是加速器，不是免责条款。

何时升档：三个判断

信号动作
产出要对外（客户、监管、全员邮件）升一档：sonnet-4-6 起，收尾 kimi-k2.6 / qwen3-max
活需要判断力而不只是加工（方案取舍、风险评估）直接旗舰档 opus-4-8，¥7 一份深度分析，别在便宜档上来回磨
便宜档改了三轮还不满意停手升档。三轮返工的时间成本早已超过档位差价

一个机制 + 一个习惯

机制：AI 没有记忆，每答一句都把当前对话从头重读一遍——对话越长，每句越贵，它还越容易被前面的旧内容带偏。习惯：换任务就开新对话。一个对话只干一件事，这是所有省钱技巧里 ROI 最高的一条。

💰 成本参考：全月天天用主力档约 ¥70，占额度一成半——用量不是你需要管理的问题，选对模型和保持对话干净才是。

要动本地文件（批量改一堆 Word、处理 Excel）→ 看 🔥 重度岗的 Claude Code 部分；知识库入库前先把资料转成干净文本（图片不参与检索），答得准不准八成定在入库这步。

长文本 / 批处理 / 数据岗：你才是"用量大户"

整批翻译、数据清洗、自动化、研究报告——集团的 token 基本是你们这类活烧掉的。这条路最长，但每一段都直接帮你省钱、少翻车。

你的主战场：Claude Code

动本地文件的活（批量文档、Excel、脚本），用 Claude Code（VS Code 插件或 Desktop）。它能直接读写你电脑里的文件，重复三次以上的活让它做成小工具，以后一键复用。

核心方法：先跑通，再放量

  1. 拿 1~3 个样本，用旗舰档跑通——把指令模板、输出格式、质检标准都定下来。
  2. 换便宜档，先跑一小批——按首批 10% 抽查的标准查三样：数字、否定句、免责/例外条款（研究证实的三大高危错误区）。小模型出错是"悄悄变差"，不抽查看不出来。
  3. 没问题再全量——大批量让 Claude Code 写脚本挨个跑。指令示例："写一个脚本：读取 D:\xx 目录下所有 docx，逐个调用【模型】按开头的模板处理，结果按原文件名存到 out\，失败的记进 errors.txt。"跑完只看 errors.txt。

这是 OpenAI / Anthropic 官方文档都推荐的标准工作流（OpenAI 官方案例：同任务成本降约 57 倍、精度不掉）。适合模板化、输出可校验的活；每件都要深度判断的活，该旗舰就旗舰。切档后如果抽查不合格率明显上升，说明这个活不适合降档——升回去，别硬省。

上下文纪律（这一节值回整份手册）

纪律为什么
一活一对话；几十个文件绝不堆一个窗口每问一次，前面所有内容全部重读——堆一窗用旗舰档，实算一次 ¥900+
大批量→脚本化，不在对话里手动逐个脚本每件只读一次；对话里逐个=重读 N 次
术语表 / 要求固定放开头，不改动各家 API 对"开头完全相同"的内容给缓存折扣（网关价目里的"缓存"列，通常 1~2 折）——开头一动，折扣全失
超长文档先分块再处理，最后合并几十万字一次喂进去，既容易超窗口、又让每轮追问都重读全文；按章节切块各自处理，只把结论汇总进最终对话
图片版 PDF / PPT 先转纯文本再喂按图片喂 token 贵好几倍；确需读图（扫描件）用视觉档专门跑，别混进文字流程
答错就回退重来，别追加"不对，再改"错误答案留在对话里，会被反复重读还带偏后续
Claude Code 换任务就 /clear长会话挂旗舰不清上下文，一场 ¥200，一周烧完额度
/context 看"工作本子"里装了什么、还剩多少 /usage 看这次花了多少、额度还剩多少 /statusline 配一次，花销常驻底部显示

管理者：你不用天天上手，但这三件事只有你能做

首月的集团画像（已脱敏）：八类职能、多个事业部都用起来了；真正跑通的集中在离交付最近的一线骨干；也有不少账户还没被激活。这不是考核，是机会分布图。

三件事

  1. 给团队圈出"值得重点支持的活"——批量单据处理、文档流水线、数据清洗这类活 ROI 最高（参考 🔥 那条路的速查表）；让做这些活的同事先跑起来。
  2. 把"先跑通、再放量"定成团队默认动作——旗舰定模板、便宜档执行、抽查后全量。一句话的管理动作，挡住绝大多数浪费和翻车。
  3. 用两个数看团队，别只看一个——金额高但用量低：查一下是不是选错了贵模型；用量高但金额低：多半是健康的自动化，值得表扬推广；两个都高：约同事聊聊在做什么项目，往往是最值得投入的场景。
📣 对团队的口径建议保持一件事：做对了，¥500 能覆盖绝大多数日常工作——要管的是姿势，不是用量。需要给团队开一场培训，找市场部 Alex 拿现场版课件。

Research done properly

After turning on web search (globe icon), two rules still apply: ① demand sources — "attach a source link to every claim"; a number without a source is a number it made up; ② cross-check key figures — market sizes, regulations, competitor prices: click through before you quote. AI search is an accelerator, not an alibi.

One mechanism + one habit

Mechanism: the model has no memory — every answer rereads the whole conversation from the top. The longer the chat, the pricier each line, and the easier it drifts on stale content. Habit: new task, new chat. One conversation, one job — the highest-ROI rule in this handbook.

💰 Cost reference: a full month of daily workhorse use runs about ¥70 — a seventh of your quota. Volume is not your problem to manage; model choice and clean chats are.

Need to touch local files (batch Word edits, Excel)? → See the Claude Code part of the 🔥 heavy lane. Building a knowledge base? Convert documents to clean text before loading (images aren't searchable) — most of your answer quality is decided at load time.

🔥

Long text / batch / data: you are the heavy user

Bulk translation, data cleaning, automation, research reports — this kind of work burns most of the group's tokens. This is the longest lane, and every part of it saves you real money.

Your home ground: Claude Code

Anything touching local files (document batches, Excel, scripts) runs in Claude Code (VS Code extension or Desktop). It reads and writes your files directly; any job you repeat three times is worth turning into a small tool.

The core method: pilot first, then scale

  1. Run 1–3 samples on a flagship model — fix the prompt template, the output format, and the quality checks.
  2. Switch to a low-cost model, run a small batch — spot-check 10% of the first batch on three things: numbers, negations, exclusion clauses (the three failure zones research confirms). Small models fail quietly; without sampling you won't see it.
  3. Then go full volume — have Claude Code write a script that runs file by file. Example instruction: "Write a script: read every docx in D:\xx, process each with [model] using the template at the top, save results under out\ with original filenames, log failures to errors.txt." Afterwards you only read errors.txt.

This is the standard workflow recommended in OpenAI's and Anthropic's official docs (OpenAI's own case: about 57× cheaper, no accuracy loss). It fits templated, checkable work; work needing deep judgment per item stays on the flagship. If the spot-check failure rate climbs after downgrading, the job doesn't fit the cheap tier — move back up, don't force the saving.

Managers: you don't need to be hands-on daily, but only you can do these three things

The group's first-month picture (anonymized): eight kinds of function across many business units are using AI; the real traction sits with frontline specialists closest to delivery; plenty of accounts are still dormant. This is not a scorecard — it is a map of opportunity.

Three things

  1. Circle the work worth backing — batch document processing, paperwork pipelines, data cleaning have the highest ROI (see the 🔥 lane's table); get the colleagues doing that work moving first.
  2. Make "pilot first, then scale" the team default — flagship sets the template, the cheap tier executes, spot-check before full volume. One sentence of management that blocks most waste and most failures.
  3. Read two numbers, not one — high spend, low tokens: check for a wrong (expensive) model choice; high tokens, low spend: usually healthy automation, worth praising and spreading; both high: sit down with that colleague — it is often the most investable use case in the team.
