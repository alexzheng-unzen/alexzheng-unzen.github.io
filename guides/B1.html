⓪开场白：三句话

立场、正名、原理，各一句，然后直奔干货。

第一句，立场：公司希望大家用得更多，不是更少。今天要治的不是「用太多」，是「空转」——白白烧掉、没换来产出的那部分 token。

第二句，正名：这门手艺有正式名字——Context Engineering（上下文工程），Anthropic 官方工程博客的标题原词。圈内也管追求的效果叫 token efficiency。

第三句最重要：AI 其实很健忘

它没有真正的记忆。你们聊过的每句话、它读过的每个文件、每个插件的说明书，全记在一个「工作记录本」里（术语叫 context / 上下文）。每次你发一条新消息，它都要把这个本子从第一页重新读到最后一页，才知道现在该干嘛——读的每一页都计费。

📌 所以只有一条总原则：本子越厚，每条消息越贵；而且越厚它越容易看花眼、抓错重点。今天所有技巧，本质上都是让本子保持薄而干净。
⭐ 本子很大，别怕用：官方说 100 万 token 的容量，用到三四十万才开始明显犯糊涂。重点从来不是少用，而是别让没用的旧内容一直占着本子。
爽感不变，续航变长。

①反面教材：最烧 token 的 7 个坏习惯

每条先讲「为什么烧」，再给改法。判断标准只有一个：这段内容会不会一直留在本子里、被反复重读。

坏习惯 1 · 唠嗑式提问：一个问题拆成三五条短句发

为什么烧：每发一条消息，它都把本子从头重读一遍。三条短句 = 同样的内容被重读三遍，它还要组织三次回答。

唠嗑式（烧三遍）

「帮我看下这个文档」
「主要是第三节」
「案例换成保险行业的」

三条消息，本子被从头读了三遍

一次说全（只烧一遍）

「把这个文档第 3 节的案例换成保险行业的，口吻不变」

想清楚一次说全；漏了条件就回退重说，别追加

坏习惯 2 · 让它看文件，但不给路径

为什么烧：它只能开搜索工具满库翻找，翻找过程一字不落记进本子——这些记录对后面的活毫无用处，却每一轮都被重读。

让它自己找

「你看一下理赔那个表格」

它只能开工具一个个翻，找完一本子全是搜索记录

直接给坐标

「看 E:\Task01\理赔明细-5月.xlsx，把直付那一列汇总」

用 @文件名 或贴完整路径，直奔目标，本子干干净净

坏习惯 3 · 「帮我优化一下」式模糊指令

为什么烧：它只能全文扫一遍、挨个猜你要什么——猜错一轮，整轮白烧。

让它猜

「帮我优化一下这个文档」

全文扫描 + 猜测，猜错就整轮重来

带坐标

「第 2 节太长，压到一半，三个案例都保留」

改哪里、改成什么样，一句话说清

坏习惯 4 · 答错了，就一直追加纠正

为什么烧：错误方案会留在本子里反复被重读，还会把后面的回答带歪——纠正本身也在烧。

追着纠正

「不对」「还是不对」「换个思路再试试」

错误路线越积越多，越聊越歪

回退重来

连按两下 Esc（或 /rewind）回到跑歪之前：「别走方案 A，直接上 B」

相当于把错的那几页直接撕掉。Anthropic 官方原话：如果只挑一个体现 context 管理水平的习惯，就是这个

坏习惯 5 · 一个会话从周一用到周五

为什么烧：周一的任务记录到周五还在被反复重读、反复计费，还会分散它的注意力。

一本用到底

周报、改稿、查数据……全挤在同一个会话里聊

本子越来越厚，答案越来越飘

换任务换本子

换任务就 /clear 开新会话

先 /rename 给旧会话起个名，想找回用 /resume

坏习惯 6 · 把图片版 PDF / PPT 原件直接喂进去

为什么烧：模型读图片版文件像隔着毛玻璃认字——费劲、容易读错，还特别占本子。

原件直接丢

30 页 PPT 原件直接拖进对话

读得稀里糊涂，答非所问

先转纯文本

markitdown 先转成 .md 再发

坏习惯 7 · 粘贴几千行日志 / 全文，让它找一个点

为什么烧：几万 token 一次性记进本子，99% 用不上，却每一轮都被重读。

全选粘贴

全选 → 粘贴 → 「帮我看看哪里报错」

一次粘贴，本子直接厚一倍

先缩小范围

先 Ctrl+F / 筛选，只贴相关的那一段

量实在大，丢给 subagent 去读（⑤节）

⚠️ 最后一个隐形坑（小红书网友实测）：会话进行中别频繁改 CLAUDE.md、别没事切换模型——这两个动作会让缓存失效，相当于让它把本子从头到尾重新读一遍、重新付费。要改配置，留到开新会话之前。

②指令工具箱：改习惯靠的不是记性，是顺手的指令

三组指令对应三件事：看账 → 清本子 → 控开工。每条都讲「怎么用」和「为什么省」。

第一组 · 看账：先知道 token 花在哪了

> /context # 翻开本子：系统提示、插件说明书、聊天历史各占多少、还剩多少 > /usage # 看消耗：额度用了多少、哪些工具最能吃 > /statusline 帮我添加模型使用上下文百分比和具体数值以及模型名称显示 # ↑ 照抄这句，它就会帮你配好状态栏，本子用量常驻可见

为什么省：看不见就管不住。状态栏常驻之后，你会自然地在本子快满前主动收，而不是被动等它犯糊涂。

第二组 · 清本子：只留有用的

> /rename 周报-6月第2周 # 换任务前先给会话起个名 > /clear # 换一本新本子开新任务（别名 /new；想找回用 /resume） > /compact 保留结论和改动 # 把几十页过程压成一页摘要，可以带指令 > /btw 这个词什么意思 # 顺嘴小问题用 /btw 问，答案不记进本子 > /rewind # 或连按两下 Esc：回退重来，撕掉走歪的那几页
⭐ /compact 和 /clear 怎么选？官方的说法很形象：/compact = 让它自己写交接摘要——省事，但它来决定什么重要，难免有损；/clear = 你自己写两句交接（在干什么、关键文件是哪几个、排除了什么路线）——费一点事，但本子是你亲手收的，最干净。同一件活干到一半用 compact，彻底换一件活用 clear。

第三组 · 控开工：方向对了再动手

> Shift+Tab # 切到 Plan Mode（或直接 /plan）：先出方案，你点头才动手 > /mcp # 关掉闲置插件——每个插件的说明书都常驻本子，像清手机后台 > /model # 模型分层：好钢用在刀刃上
任务类型用谁为什么
日常写作、整理、改稿Sonnet速度快、能力够用，日常主力
批量小任务（subagent）Haiku跑得飞快，量大的活最划算
复杂方案、深度思考Opus好钢用在刀刃上，/model 随时切
💡 进阶一档（用熟了再做）：CLAUDE.md 每次对话都会全文进本子，当查找表用、别当百科全书写，官方建议 200 行以内；专项流程搬去 Skills，用的时候才加载。小红书一篇 3400+ 赞的实践帖还补了一刀：全局配置（~/.claude）保持接近空白，项目相关的内容放项目里——不同项目的信息互相串扰，你就得花 token 去纠正它的错误记忆。

③任务分级：多大的活，怎么开工

指令是零件，这一节是装配图——接到一个活，先掂量体量，再决定怎么开工。

体量特征开工方式
小活一次性、几分钟能完带坐标直接问，不用任何仪式
中活要半天、跨多个文件、做错要返工Shift+Tab 先进 Plan Mode——它先摆方案，你点头了才动手。方向对了再开工，是体感最强的一个开关
大项目持续几天、资料几十个文件先让便宜模型写一份索引（下面演示）
重复活每周都要跑一遍固定下来：脚本 / 浏览器本地工作台 / 打包成 skill（④节）

演示 · 给大项目写索引：贴一次货架标签，之后取货不翻仓库

大项目最烧的地方在于：每个新会话它都要重新翻一遍几十个文件搞清楚状况。解法是让便宜模型先把仓库整理成一页标签：

# 第一步（用 Haiku 跑，便宜模型干粗活）： > 通读这个项目文件夹，把每个文件用一行话总结（路径 + 它是干嘛的）， 存成 PROJECT-INDEX.md # 之后每个新会话，开头一句： > 先读 PROJECT-INDEX.md，再开工 ✓ 它直奔目标文件，不再满库翻找

原理：索引一页纸只占几百 token，常驻本子毫无压力；换来的是每次都省掉「满库翻找」那几万 token 的无效记录。便宜模型贴标签，贵模型直奔货架。

④Skills 装备：固定下来的活，还能互相分发

重复活固定成 skill 之后就成了团队资产——今天现场发两件。但先养一个习惯：装前安检。

装前先安检：习惯比工具重要

🔒 skill 本质是一段会直接写进 AI 记录本的指令文本。来路不明的 skill 可能藏着坏指令——让它悄悄执行危险命令、把数据发到外面。任何来源的 skill，装之前先让 Claude Code 自己审一遍：
> 先别安装。读一下这个 skill 文件夹里的所有文件，告诉我： 它会让你执行哪些命令？读写哪些位置？联不联网？ 有没有可疑或者越权的指令？ ✓ 审完没问题，再装

⑤超级进阶：Agents 混用，打组合拳

前面都是「一个 Claude 怎么用好」，这一节是「一队 AI 怎么配合」。听个思路就行，不要求今天上手。

入门：subagent——自带本子的实习生

批量处理、通读长资料、多源查证——这类「过程不用看、只要结论」的活，直接对 Claude 说一句：

> 这 30 份资料的要点整理成一张表，开个 subagent 去做 ⏺ 已派出 subagent 处理…（过程记在它自己的本子上） ✓ 完成 只有结论记回你的本子，主对话始终干净

分工原则：按「过程要不要进你的本子」分，不按职位分。中间过程需要你盯着的，留在主对话；量大、只要结论的，才丢给 subagent。小红书一位用了一年的用户（209 赞）说得很干脆：从不预设"前端/后端/PM"一堆角色。

组队：不同的 Agent，不同的长处

工具定位长处价格档位（2026-06）适合交给它的活
Claude Code我们的主力（Anthropic）社区盲测里代码质量评分最高；生态最全：skills / subagent / 插件 / Plan Mode公司 Team Plan，放心用主控位：日常一切，重要的活都从这里发起
CodexOpenAI 的终端 Agent（编程专用模型）速度快；云端沙箱能跑跨天长任务；终端/脚本类活实测强跟 ChatGPT 套餐走（$20 / $100），和 Claude 同一档快速原型、批量小修、给 Claude 的产出做交叉审查
Kimi月之暗面的终端 Agent（K2.6）便宜是第一卖点；中文场景好、国内网络无障碍、输出快国内 ¥49/月起，比前两位便宜一截中文需求、大批量低风险的活、个人低成本入门

一句话记住：质量找 Claude，速度找 Codex，量大找 Kimi。另有 Cursor（带图形界面的编辑器，$20/月起）适合不爱终端的同事；Gemini CLI 免费但个人版 2026-06-18 起停服，不推荐新入坑。

它们之间怎么传话？四个办法，从土到洋

  1. 交接文件（老办法，依然好用）：A 干完把「在做什么 / 关键文件 / 做到哪了」写进 README.md，B 开工先读它。零门槛，今天就能用。
  2. 结构化任务卡（升级版）：交接文件里写明验收标准——「改完后这三个功能必须正常」。B 不光知道干什么，还知道干到什么程度算完。比裸 README 可靠得多。
  3. AGENTS.md 公约（行业新标准）：项目规则写一份 AGENTS.md，所有 agent 共读——Codex 原生认它，Claude 认 CLAUDE.md，互相引用一下就拉通了。一处维护，全队对齐，我们办公室已经在用。
  4. 直连插件（最出效果，官方背书）：OpenAI 官方出了 Codex plugin for Claude Code——Claude 写、一句话叫 Codex 来独立审查，不需要文件中转，还消除了「自己审自己」的偏袒。我们已装好。
⭐ 真实战绩：谁写的，让另一个来审。绩效系统上线前，用 Claude Code 写、让 Codex 做全栈审查，一个下午揪出 5 个 P0 级漏洞。两个 agent 互为审查员，比一个 agent 自己复查自己靠谱得多。
⚠️ 多 Agent 并行什么时候开：量大、可并行、赶时间（比如一晚上扫几十份资料）才值得——每个队友都自带一个本子，速度快、消耗也大。日常小活，单个 subagent 就够；干完记得收队。

⑥现场动手 + 回去三件事

两条命令，翻开自己的本子看看——每个人的都不一样，挺有意思。

> /context # 翻本子：哪些东西一直记在里面、还剩多少 ⛁ 系统提示 … ⛁ MCP 工具 … ⛁ 记忆文件 … ⛀ 剩余空间 … > /usage # 看消耗：哪些工具最能干（也最能吃）

看到结果别紧张——占用本身不是问题，放着不用的占用才可惜。对照第①节的黑名单整理一下就好。欢迎把截图丢到 AI 群互相参观，看看谁的本子最干净。

  1. 跑一次 /context，截图丢到 AI 群——互相参观本子，互相偷师。
  2. 对照黑名单，挑一个自己中招最深的坏习惯改掉——建议从「提问一次说全 + 带文件路径」开始。
  3. 装上今天发的两件装备——装之前，先让 Claude 安检一遍，把这个习惯也养上。
额度是用来花的，放心用。今天的技巧只是让你爽得更久。
